# A recorded read-only capstone pipeline

The [first capstone stage](../labs/capstone/README.md) connects trusted source filtering, lexical retrieval, whole-request packing, a model answer, and separate provenance/reference checks. It compares one versus up to three source chunks over eight frozen authored questions. Two development questions retain retrieval traces only. The [results](../labs/capstone/RESULTS.md) preserve every actual answer and explain failures individually.

This is useful for developers who have read the component labs and want to follow the complete path from question to checked answer. Start by comparing the deployment-conflict case: one retrieved current decision can support a plausible answer while hiding another current decision. Then inspect the direct-answer case, where identical input produces wording variation and the strict matcher rejects a semantically equivalent response. An aggregate score can hide both an evidence problem and an evaluator problem.

The new offline checker joins the repository regression gate. Twelve tests cover host behavior and runner failure fixtures; those fixtures are distinct from the sixteen actual model calls. Exact tokenizer replay is available with cached pinned assets. MiniLM token counts are explicitly a proxy, not the hosted generator's token accounting or an enforced output limit.

This is an authored fictional pilot, not independent validation or a benchmark of general reliability. It implements the read-only stage; integrated recovery and reviewed updates remain unfinished. Human feedback, independent annotations, judge calibration, and recurring editorial continuity remain open.
