# Single call, fixed workflow, or agent? — 2026-10-19

Two authored library tasks from the existing grounding corpus: routine (superseded draft plus current-plan) and conflict (those documents plus alternate-current). Compare three execution strategies, with two repetitions of each task/strategy, for twelve task runs. First repetition order: single, fixed, agent; second: agent, fixed, single. No parameter tuning or replacement runs after viewing outcomes.

Single: one model call receives all task documents. Fixed: the host deterministically selects every document with status=current, then one model call answers. Agent: the model chooses search/read/final JSON actions through the same read-only dispatcher used by bounded-agent; search supplies metadata, not document text. Both current sources remain discoverable in the conflict case. The fixed rule is handcrafted for this metadata and task, not a generally superior retriever. Single/fixed share the exact answer prompt; the agent needs a different action-format prompt. This is an end-to-end architecture comparison, not an isolated prompt experiment.

Use gpt-6.1-sol with low reasoning through Codex, at most six calls per agent run and one per other run: at most 32 model calls total. Each call has a 180-second timeout; a failed model call stops that task and remains retained. No external writes. Save every request, raw output, log, tool result, final answers, and before-run code/prompt/corpus snapshots. Grade with the same authored reference rules as evidence-grounding. Record process success separately from answer correctness and resolved questions.

Report per-task/repetition correctness, model-call counts, summed call durations, and total request characters. Character counts are not token usage or billing; dollar cost is unmeasured. Do not attach significance claims to two repeated authored tasks. More autonomy may add overhead without benefit; retain ties and regressions. All results are local demonstrations, with independent human review pending.
