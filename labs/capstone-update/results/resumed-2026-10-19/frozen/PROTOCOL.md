# Frozen integrated update protocol

Use the three authored fictional documents, original project material under the root MIT license. The current team-a decision changes a disposable plan from 13:00 to 14:00 while preserving capacity 20. Superseded and other-scope records are filtered before search/read. Metadata and checkpoint storage are trusted local fixtures, not authenticated services.

One actual model-directed run may use search, read, propose, or unresolved actions. Maximum six calls, requested gpt-6.1-sol with low reasoning effort, 180-second process timeout per call. Reserve and save the call count before inference. Parse at most 8192 output bytes, reject duplicate JSON keys and unknown fields. Stop on process failure or exhausted budget. An uncertain pending call refuses automatic resume. No native output-token or dollar cap is claimed. Input requests have a 16000 UTF-8-byte host ceiling, counted including full history; this is a size guard, not token/context-window accounting.

Inject exactly one temporary failure on the first permitted read. Stop at that completed host event and persist its checkpoint. Resume in a fresh runner process from the saved state; the budget and fault-used flag must survive. Retain every exact request, final output, process result, duration, action, host result, checkpoint, and source/code hash. Model CLI stdout/stderr and hidden reasoning are not retained. A CLI read-only sandbox is not complete process or network isolation.

A proposal must bind a fixed target, original-content hash, complete replacement, and an exact unique quotation from a current permitted document read in this run. Host-resolved quote offsets prove location, not semantic support or authorized approval. Incorrect but well-formed proposals remain possible. The model has no application approve/apply operation.

After the model run ends, a **scripted reviewer fixture** independently compares the proposed complete content with the frozen expected replacement and verifies its resolved quote includes the exact phrase `change the start time to 14:00` from the approved decision; the complete replacement comparison separately verifies preserved capacity. Only that fixture may approve. It is not a human reviewer or independent annotation. If the fixture rejects the proposal, retain the failure; do not rerun inference or silently repair it.

For an accepted proposal, execute in a new temporary directory: reject apply-before-approval; approve the exact proposal; reject tampered content; reject an independently modified stale target; apply to the original target; verify exact final bytes; repeat in the same process and require already_applied. These are deliberately authored host probes against a real proposal, not observed model bypass attempts. Reuse the approval gate byte-for-byte from the earlier action-approval lab and retain its limitations: in-memory approval state, no concurrent writer, no durable distributed exactly-once guarantee, no user authentication.

Success means a bounded resumed trace reaches a reviewable evidence-linked proposal, preserves all original observations, and the separate scripted review/apply checks behave as declared. Report actual calls and failures without broad reliability claims. A failure is a reportable result. This complements the first capstone's retrieval comparison; it is not a comparative trial or human-approval study. Unit tests separately cover denial, malformed actions, stale proposals, uncertain calls, and budget exhaustion.
