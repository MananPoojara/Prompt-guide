# Review a change

**Use:** For a diff with known requirements.

## Copy and adapt

```text
Review this diff against [requirements]. Prioritize concrete correctness, compatibility, and security defects. For each finding, give the triggering condition, file location, impact, and evidence. Verify suspected issues when feasible. State what was not checked. Avoid inventing findings to fill a quota.
```

## Check the result

Each finding can be reproduced or supported by a clear code path.

## Watch for

Style preferences presented as correctness defects.

Start with the shortest version that communicates the task. Add examples when ambiguity affects the result.
